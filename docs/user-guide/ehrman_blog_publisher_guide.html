1. Introduction

Use this guide to publish articles, maintain search content, and review AI usage. The Quick Guide links to the instructions for each WordPress screen.

1.1 Quick Guide

Sign in using your own WordPress account. These management screens require appropriate administrator permissions. Contact your site administrator if a menu or action is unavailable.

1.2 What Is Search Metadata?

Search metadata is information about an article that helps readers find relevant posts. The description briefly identifies what the article covers; the summary gives a fuller account of its key points. Topics identify its main subjects, and secondary keywords identify meaningful details, such as people, texts, or events.

A vector is a numerical representation used by Ask AI to match a reader's question with relevant articles. The plugin creates it after metadata approval; you do not enter or edit vector values.

Demo screenshots include illustrative metadata and empty analytics; your site's layout and values may differ.

2. Adding a Post

2.1 Write and publish an article

Open Posts > Add Post. Choose the metadata mode before first publication.

  1. Enter the Title, select the Author, and enter the article in Post. Use Visual for formatted editing; Code exposes the underlying markup.
  2. Use Save Draft while working and Preview to check the article. To schedule publication, edit the date beside Publish immediately.
  3. Under Metadata Generation, choose Manual to review before approval, or Automatic to generate and approve without a separate review. The site's current choice is marked (site default).
  4. Select Publish, or Schedule for a future date. Metadata is created only after publication, not while the post is a draft.

The mode choice is saved with this post and is locked after first publication. Changing the site default affects new posts, not previously published articles.

2.2 Choose Manual or Automatic

Both modes start with the same article form. The difference is whether a person reviews the generated metadata before it is added to search.

Manual: review before approval

  1. Before publishing, select Manual under Metadata Generation. Publish the article when it is ready.
  2. After publication, select Create Metadata in the editor's Post Metadata panel, or open the article from Blog Search > Post Metadata.
  3. Wait for generation, review the proposed metadata, and approve it. The vector is created after approval. See Section 3.1: Create, review, and approve for the detailed review steps.

Automatic: generate after publication

  1. Before publishing, select Automatic. Publish the article, or schedule it for later publication.
  2. After first publication, the plugin generates and approves metadata and creates the vector in the background. You return to the Posts list; you do not need to stay on the Add Post screen.
  3. Use the publication notice's View Metadata link, or return later to Blog Search > Post Metadata. Check completion or respond to any issue using the status and follow-up guidance.

What stays the same

  • Publish first. Saving a draft does not generate metadata, and a scheduled post waits until publication.
  • Publishing the article and completing its search metadata are separate stages. In Manual mode, the publisher must initiate generation and approve the result.
  • Automatic mode normally needs no manual approval, but failures or safeguards may still require attention. Later article edits do not automatically regenerate metadata.

The site's current mode is marked (site default) in the form. You can override it before first publication; the post's choice is then locked. Administrators set the default in Settings (Section 6.1).

3. Post Metadata

3.1 Create, review, and approve

After publishing, use the Post Metadata panel in the editor, or open the post from Blog Search > Post Metadata.

  1. Select Create Metadata. Wait for the progress indicator to finish and the generated fields to appear.
  2. Read the Description and Summary. Correct inaccurate wording without changing the article itself.
  3. Check Topics and Keywords. Select the x to remove an unsuitable item; restore it if needed.
  4. To add an existing term, select Add topic or Add keyword. Click in the box to browse alphabetically, or type to filter. Select one result; the picker closes. Repeat to add another.
  5. Select Approve and Add to Search. The plugin saves the approved metadata and then creates the vector.

Before approving

Keep the topics focused on sustained subjects and keywords on meaningful details. Keep at least one topic. The Add controls select existing vocabulary; they do not create new terms.

On the separate review page, Save revisions saves your draft without approving it. Regenerate Metadata requests a new proposal and can incur another AI charge. Discard draft discards the metadata proposal, not the WordPress article.

3.2 Check progress and revise metadata

Open Blog Search > Post Metadata to find articles needing attention, check either generation mode, or revisit an approved record.

  1. Open Blog Search > Post Metadata, or use a post's View Metadata link. This is the editorial worklist, not the cost-reporting tab inside AI Analytics.
  2. Search by Post title, or use the Status and publication-date filters. All is the default. Clear filters only resets the filters; it does not delete data.
  3. Look for Complete in the worklist's Status and Vector columns. A detail screen may say Approved for the metadata. Vector completion confirms the Ask AI indexing stage.
What you seeWhat to do
Not generatedOpen the post's action and select Create Metadata when ready.
GeneratingAllow the current request to finish. Reopen or refresh the status page later; do not repeatedly submit new requests.
Needs approvalOpen the review, check the fields, and approve them.
Failed / ErrorOpen the details and read the message. Correct the stated issue before retrying. Contact your administrator if it persists.
Vector errorUse Retry Vector in the editor, or Retry semantic vector on the detail page, when offered. This retries the vector stage without regenerating the metadata.
Not applicableA vector is not required for this type of excluded post; this is not itself a failure.

Changing approved metadata

Open the approved record and use Edit Metadata to revise it, or Regenerate Metadata for a fresh proposal. Review and select Approve Changes. The previous live metadata remains in use until the revision is approved.

Updating the article does not automatically regenerate its metadata. Save or update the article first. If the plugin reports that the source changed, regenerate from the saved post. An imported record without an editable local WordPress post may be view-only; ask your administrator.

4. Managing Topics

4.1 Find an item in Manage Topics

Open Blog Search > Manage Topics. The tabs are Subject Areas, Categories, Topics, and Export. Subject Areas opens by default.

  1. Choose the appropriate tab and click in its search box. An alphabetical list opens before you type. Scroll within the list to reveal more choices.
  2. Type any part of the name to narrow the list. Clear the text to show all choices again. Click a result to open its relationship editor; there is no separate Search button during normal use.
  3. Use Browse All for the full alphabetical directory, or View All Matches when offered for a longer result list. These directories have page controls. Clear Search returns to the search-first view; it does not delete anything.
  4. In the Categories directory, each row shows its linked Subject Areas and Topics. Select Show all N topics to expand a longer list, or Show fewer to collapse it. Select the category name to edit it.

Keyboard: use the arrow keys to focus a suggestion, then Enter to open it. Enter while still in the search box opens the full matching results. Escape closes suggestions. If live suggestions are unavailable, a Search button remains as a fallback.

4.2 Create a new item

Subject Areas group Categories; Categories group Topics; Topics are assigned to posts. Create only what is missing, then link it to existing items.

  1. Search for the proposed name first to avoid a duplicate. The Add button remains beside Browse All, even when you are using suggestions.
  2. Select Add Subject Area, Add Category, or Add Topic. Enter a unique name and a required description. Use the guidance and example beside the description field.
  3. Choose any required links using Add category, Add subject area, or Add topic within the form. Browse the choices or type to filter, then select an item. The picker closes after each selection; press its Add button again to choose another.
  4. Review the name, description, and links, then select Create Subject Area, Create Category, or Create Topic. Selecting links alone does not save the new item.

Which links are required?

New itemRequired links
Subject AreaCategories are optional; an empty Subject Area can be created first.
CategoryAt least one existing Topic. Subject Areas are optional.
TopicAt least one existing Category.

What changes after creation?

  • A new Topic is available for future metadata generation and for adding to a post's metadata. Existing articles are not automatically assigned to it.
  • A Topic with zero posts can still appear in Browse Topics under its linked Category. That Category must be linked to a Subject Area to be reached through the browsing hierarchy.
  • A Category without a Subject Area stays in Manage Topics for later linking. It is not included in the public subject-area hierarchy or its PDF/CSV exports.

Top-level Add creates a new item. The Add controls inside a relationship form only link existing items. Existing names are read-only, so check the name before creating it.

4.3 Maintain links and descriptions

A Category may belong to several Subject Areas. A Topic may belong to several Categories. Adding a link does not remove its other links.

  1. Find and open an existing item. Its name is read-only; this screen does not rename it.
  2. Use Add category, Add subject area, or Add topic to browse or filter existing choices. Selecting one closes the picker; press Add again for another. Use the x to remove a link.
  3. Select Save Category Links for a Subject Area or Topic, or Save Relationships for a Category. Add/remove selections are not saved until then. Unlinking does not delete items or remove a Topic from posts.
  4. Save relationship changes before opening Edit Description. Revise the explanation and select Save Description, or Cancel to leave it unchanged. These are separate saves.

Write useful descriptions

  • Subject Area: explain the broad scope in about 20-40 words.
  • Category: explain the shared theme of its Topics in one or two clear sentences.
  • Topic: define the specific subject and useful boundaries in about 25-50 words. Preserve its existing meaning; do not repurpose it into a different topic. These are guidelines, not required word counts.

Topic descriptions guide future AI assignments. Changing one does not retag approved posts, but pending proposals using the old vocabulary require regeneration before approval.

4.4 Delete carefully; export the outline

Deletion is different from unlinking

  1. If deletion is disabled, an administrator must enable Allow Deletion in Blog Search > Settings. See Section 6.1 for that setting.
  2. Return to Manage Topics, open the item, and find Delete below its relationship form. If disabled, read the explanation and resolve the stated blockers first.
  3. Select Delete, inspect the confirmation and affected links, then select Permanently Delete only if correct. Consider disabling deletion again after cleanup.
  • Deleting a Subject Area, even an empty one, preserves its Categories, Topics, and posts. Categories with no remaining Subject Area stay in Manage Topics for relinking.
  • Deleting a Category is blocked if a Topic would lose its last Category. Link those Topics to another Category first.
  • Deleting a Topic is blocked while it is assigned to posts. It does not silently strip that Topic from articles.

These deletions cannot be undone on this screen. They do not delete WordPress articles or other linked records. Use unlinking when you only want to reorganize an item.

Download a PDF or CSV

Choose Export, then Entire structure or Selected Subject Areas. Check one or more areas for a selection, then choose Download PDF or Download CSV. Both are alphabetical; shared items repeat under each parent. Unlinked Categories and Topics are omitted. This outline is not a backup of posts, metadata, or vectors.

5. AI Analytics

5.1 Start with Overview

Open Blog Search > AI Analytics. Overview combines the costs of reader questions and post metadata generation.

  1. Choose Today, This month, or All retained. The selected shortcut is highlighted.
  2. For a custom period, enter From and To and select Apply filters. Clear removes the date restriction; it does not erase history.
  3. Read Total estimated cost, then compare Ask AI cost with Post Metadata cost. Use the activity links or tabs to examine either area. Date filters carry across the tabs.

How to interpret the totals

  • Questions counts reader search requests; Metadata generation runs counts generation runs, not unique articles.
  • All retained means all records still held by the plugin, not necessarily all historical account spending.
  • Amounts are estimated US-dollar costs based on recorded usage and pricing. Confirm billed amounts in the OpenAI account. Calls made outside this plugin are not included.

Report dates use Eastern time. Ask AI groups costs by question submission date; Post Metadata uses the date of each API call. A metadata run spanning a date boundary can be only partly included in a filtered total.

5.2 Review Ask AI usage

Use the Ask AI tab to see search volume, estimated costs, and how many posts were returned.

MetricMeaning
Total estimated costQuery-vector creation plus AI review of candidate posts, within the current filters.
Average cost per questionEstimated total divided by the question count. The card displays cents, not dollars.
Average posts returnedThe average number of results. More results does not, by itself, mean better relevance.
Zero-result questionsQuestions that returned no posts. Review their wording and results before deciding whether search needs improvement.

Inspect and download questions

  1. Select a date range. To focus on unsuccessful searches, check Zero results and select Apply filters.
  2. Read the Questions table. It shows the question, cost, result count, source, and token usage. AI review details provides more technical detail when needed.
  3. Select Export questions CSV to download records matching the active filters. Treat question text as potentially sensitive when sharing the file.

A cached question may reuse earlier work and cost less. The Cost by period table lower on the page shows its own Today / This month / All retained totals, independently of the filters above.

5.3 Review post metadata costs

Use the Post Metadata tab inside AI Analytics for costs. Use Blog Search > Post Metadata for creation, review, and approval.

  1. Choose the reporting dates. Read Total estimated cost, Average cost per generation run, and Generation runs.
  2. Find the article in Generation runs. Expand its generation details when you need to understand the charges making up the total.
  3. Select Export metadata costs CSV to download the filtered cost records for further review.

A run is not the same as a post

Generating metadata again starts another run, even for the same article. Retries within a run remain part of that run. The total includes both the metadata request and its post-vector work. For example, generating an article twice can produce two runs for one article.

  • Small vector charges can round to $0.0000; that display does not always mean the work was free.
  • A failed attempt may still have a recorded charge. Follow any warning about missing usage or incomplete estimates.
  • Cost history can remain after an article is deleted. Deleting an article does not undo earlier API spending.

To act on a post, use Section 3.1: Create, review, and approve. For unexpected costs, missing usage, or persistent errors, follow the support guidance in Section 6.2.

6. Settings, Info & Documentation

6.1 Set the site defaults

Open Blog Search > Settings. These administrator settings control the default metadata workflow and whether organization items may be deleted.

Metadata Generation

  • Manual: the publisher creates and reviews metadata, then approves it. The vector is generated after approval.
  • Automatic: the plugin generates and approves metadata and creates the vector after a new post is first published.

This sets the default for new posts. Each post can override it before first publication. Changing the site default does not process existing articles or change an already saved per-post choice. See Section 2.2 for the publishing workflows.

Allow Deletion

Disabled, the initial default, prevents deletion of Subject Areas, Categories, and Topics. Enabled makes deletion available to administrators, subject to confirmation and the safeguards in Section 4.4. It does not delete anything by itself.

Confirm that a change was saved

Select a radio button and wait for Saved; there is no separate Save button. If an error appears, follow the message and reload to confirm the stored setting before continuing. These controls require JavaScript.

6.2 Find documentation and system info

Open Blog Search > Info & Documentation. This read-only page provides the publisher guide and information about the installed plugin and search index.

Select Read Guide to open the Ehrman Blog Publisher Guide in a new browser tab, or Download PDF to keep a copy for offline reading or printing. Both copies are included with the installed plugin.

Status itemWhat it means
Plugin versionThe installed plugin release. Include this when reporting a problem.
Schema versionThe version of the plugin's database structure. This is not the WordPress or MariaDB version.
Database connectionConnected means the plugin can reach its database. If Unavailable appears, ask the site administrator to investigate.
Import stateThe recorded state of the search-data import. Complete does not mean every new post has metadata or a completed vector.
Imported postsThe number of article records in the discovery index. It is not a count of every WordPress post or draft.
Topics / Secondary keywordsThe vocabulary records stored in the search index, not the number of assignments to individual articles.

Use the right screen for the question

  • Is this article ready for search? Use Post Metadata and check both its metadata and vector status.
  • What did generation cost? Use AI Analytics and select the relevant date range.
  • Why is a Delete button disabled? Check Allow Deletion, then read the item's safeguard message in Manage Topics.

When to contact your site administrator

Ask for help if generation stays stuck, retries repeatedly fail, the database is unavailable, or an expected action is missing. An unexpected import state or count also needs investigation; do not rebuild or reload data as a routine publishing step.

Include the article title when relevant, the exact message, the approximate time, and the plugin version. A screenshot can help, but do not include passwords or API keys.

Installation, AI-account configuration, backups, and infrastructure troubleshooting are covered by the separate developer documentation.
